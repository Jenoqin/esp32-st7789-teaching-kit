2全引脚地图（谁在干什么）

按功能筛选查看。ESP32 共 34 个可用 GPIO，这块板子只占用了少数几个。

引脚角色方向电气实测 (2026-09-30)讲解 / 注意
GPIO23屏幕 MOSI输出 → 屏main.py 配置为 SPI数据线：命令与像素都从这走。屏丝印叫 SDA，实为 SPI MOSI。
GPIO18屏幕 SCK输出 → 屏main.py 配置为 SPI时钟线，固定 20MHz。超 20MHz 实测会崩溃重启。
GPIO5屏幕 CS输出 → 屏空闲高电平片选（低有效）。也是 strapping 脚——上电需为高，与 CS 空闲高正好一致。
GPIO2屏幕 DC输出 → 屏main.py 配置为输出低=命令 高=数据。⚠ 板载蓝灯可能与它并联，刷屏时灯会闪；勿挪作他用。
GPIO4屏幕 RES输出 → 屏main.py 配置为输出硬件复位线：拉低 20ms 再拉高，让驱动 IC 回到初态。
GPIO19屏幕背光 BL输出 → 屏main.py 配置为输出拉高点亮背光。屏幕全黑先查它。
GPIO34代码假接 miso（无线）浮空 读0代码里写了 miso=34，但屏幕 8P 版本没引出 SDO——所以永远读不到屏幕数据。
3V3电源输出→ 屏 VCC3.3V屏幕供电。部分同型号模块可接 5V（板载稳压），要核对模块标注。
GND公共地→ 屏 GND0V所有信号的参考点。共地不良 → 花屏、乱点。
VIN未接——5V 输入口（USB 供电时已有电）。本项目未用。
GPIO1U0TXD输出 → CP210x串口忙串口发送。经 CP210x 到电脑 COM3 @115200，REPL 和日志都走这里。
GPIO3U0RXD输入 ← CP210x串口忙串口接收。DTR/RTS 还连着复位电路——打开串口会触发一次复位。
GPIO0BOOT 键输入外部拉高 = 1上电时按住（低电平）→ 进下载模式。实测高电平 = 按键电路在上拉，工作正常。
GPIO12MTDI输入读 0strapping：决定 Flash 电压。必须保持低，接错东西可能变砖。
GPIO15MTDO输入读 1strapping：控制启动日志输出。实测高，正常。
GPIO13空闲—浮空 [0,1,0]led-pin13.py 的点灯脚本在这里，但实测当前没接 LED（上拉仍读 1）——做实验需临时外接 LED+限流电阻。
GPIO14空闲—浮空 [1,1,0]无连接，可自由使用。
GPIO16空闲—浮空 [0,1,0]无连接（WROOM 模组无 PSRAM，此脚可用）。
GPIO17空闲—浮空 [0,1,0]无连接，可自由使用。
GPIO21I2C 默认 SDA—浮空 [0,1,0]浮空 ⇒ I2C 总线上没有接任何设备（不用再扫）。
GPIO22I2C 默认 SCL—浮空 [0,1,0]同上，I2C 为空。若以后接 I2C 器件，用这两个脚最省心。
GPIO25空闲—浮空 [0,1,0]可作 DAC1 / ADC2。
GPIO26空闲—浮空 [0,1,0]可作 DAC2 / ADC2。
GPIO27空闲—浮空 [0,1,0]可作 ADC2 / 触摸。
GPIO32空闲—浮空 [0,1,0]可作 ADC1 / 晶振。
GPIO33空闲—浮空 [0,1,0]可作 ADC1 / 晶振。板载彩灯常见接法。
GPIO35仅输入输入浮空 读0无内部上拉/下拉，必须外接。
GPIO36 GPIO39仅输入 (VP/VN)输入浮空 读0ADC1 检测通道，适合接传感器模拟输出。
EN复位按键——按下 = 芯片复位，main.py 重新执行，屏幕重画一遍。

3空闲引脚电气实测——"怎么知道线上有没有东西？"

不接示波器也能查"连线"：把引脚配成输入，分别用内部上拉、内部下拉各读一次， 对比三个读数就能判断线是浮空、被拉高还是被拉低。

判读方法（本页表格数据的来历）

三种读数 [无上拉, 上拉, 下拉]结论
[ x, 1, 0 ]浮空 —— 线上什么都没接（上拉能拉到 1，下拉能拉到 0）
[ x, 1, 1 ]被外部拉高 —— 接了电源/上拉电阻（下拉都拉不下来）
[ x, 0, 0 ]被外部拉低 / 重负载 —— 接了地、按键按下或 LED 等（上拉都拉不上去）
💡 讲解点：GPIO34–39 是"仅输入"引脚，芯片内部根本没有上下拉电阻，读数永远不可靠—— 这就是它们必须外接电阻的原因。这版的固件还裁掉了 esp32.hall_sensor() / mcu_temperature() / 触摸，调了会直接 AttributeError。

屏幕初始化关键命令（精简版）

命令作用为什么需要
RES 拉低 20ms硬件复位让驱动 IC 回到已知初态
0x01 / 0x11软复位 / 退出睡眠刚上电的屏幕在"睡觉"，不叫醒就写不进
0x3A = 0x55设为 RGB565每个像素 16 位（2 字节），和后面写的数据格式对上
0x2A / 0x2B设写入窗口 0–239 × 0–239这块屏 rowstart=0，与网上常见的 80 不同，照抄会偏移
0x21 (INVON)颜色反色IPS 面板必须开，否则红绿颠倒
0x2C + 数据写显存之后每 2 字节 = 1 个像素，一行行刷完 240 行
✅ 验证小技巧：复位板子，看到蓝底白字 Hello, Yangyang + 串口末尾 HELLO SHOWN， 就证明屏幕、SPI、供电、共地全部正常——这是每次接线后的标准自检动作。

5必须遵守的工作参数

SPI 速率
≤ 20 MHz
40MHz 实测 Guru Meditation 无限重启；写进 main.py 会变上电死循环
SPI 模式
SPI(1) · CPOL=0 CPHA=0
改极性/相位会导致花屏或无显示
分辨率 / 行偏移
240×240 · rowstart=0
网上 240×240 示例多用偏移 80，照抄画面会整体偏移
色彩格式
RGB565 + 必须 INVON
不开 0x21 反色，颜色全部反相
数据方向
只写不可读
无 MISO 引出，读寄存器/ID 永远是 0xFF——不是故障
串口
COM3 · 115200 · 独占
Thonny / esptool / 脚本同时只能一个占用；打开会复位板子

6教学红线（都是踩过的坑）

🚫
别把 SDA/SCL 当 I2C
屏丝印像 I2C，实际是 SPI。按 I2C 接或执行 I2C.scan() 盲扫，会抢占 GPIO18/19，屏幕当场熄灭。
⚡
SPI 不许超 20MHz
40MHz 直接崩溃重启；如果写进了 main.py，就要抢在启动瞬间 Ctrl+C 再删文件。
📌
GPIO2 = 屏幕 DC，别挪用
板载蓝灯若与 DC 并联无法软件分离；点灯实验请用 GPIO13 等空闲脚（外接 LED）。
🔒
串口是独占资源
报"拒绝访问"先关 Thonny；打开串口会触发复位，发命令前等 3–5 秒。
🙈
别指望从屏幕读数据
无 MISO。曾盲扫 4080 种引脚组合找回读线，零命中——物理上就没有这条线。
🧩
被裁剪的 API 别硬调
这版固件没有 esp.flash_id() / esp32.hall_sensor() / 触摸；芯片信息用 esptool 查。
